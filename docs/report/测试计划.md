# 校园跑腿系统测试计划
## 1. 测试目的
全面检测校园跑腿系统各项业务功能是否正常运行，验证用户下单、跑腿员接单、订单流转等核心流程是否通顺，排查系统使用过程中的错误与漏洞，确保系统稳定流畅，满足校园日常跑腿服务使用需求。

## 2. 测试人员
测试组成员

## 3. 测试环境
- 操作系统：Windows
- 运行环境：项目本地启动环境
- 数据库：MySQL
- 测试浏览器：主流网页浏览器
- 网络环境：正常局域网、校园网络

## 4. 测试范围
1. 用户端：注册登录、个人信息管理、发布跑腿订单、订单查看、订单取消、确认收货
2. 跑腿员端：账号登录、订单浏览、订单接单、配送完成、收益查看
3. 核心业务：完整下单-接单-配送-完成全业务流程
4. 基础功能：页面跳转、信息录入、操作提示、数据加载

## 5. 非测试范围
1. 高并发压力测试、大型服务器性能测试
2. 真实线上支付转账功能测试
3. 系统底层代码优化与架构优化
4. 页面外观精细化美化调试

## 6. 主要测试内容
### 6.1 登录注册测试
- 正常账号密码登录是否成功
- 新用户注册信息提交是否正常
- 错误账号、错误密码是否弹出提示
- 退出登录功能是否生效

### 6.2 用户下单功能测试
- 正常填写取件地址、收货地址、物品信息、跑腿费用
- 完整信息能否成功发布订单
- 空内容、违规内容提交是否进行拦截提醒

### 6.3 订单管理测试
- 用户可正常查看个人所有订单
- 待接单、已接单、已完成订单分类展示正常
- 未接单订单支持正常取消操作

### 6.4 跑腿员功能测试
- 跑腿员账号正常登录进入接单界面
- 可正常查看平台全部待接订单
- 接单后订单状态实时同步更新

### 6.5 全流程业务测试
用户发布订单→跑腿员接收订单→跑腿员完成配送→用户确认订单完成，全程状态无错乱。

### 6.6 个人中心测试
- 用户可修改个人基础资料
- 可查询历史所有订单记录
- 跑腿员可查看接单数量与收益明细

### 6.7 异常场景测试
- 未登录禁止使用下单、接单等核心功能
- 重复提交订单无数据错乱
- 页面刷新、重新进入后数据保存正常

## 7. 测试方法
采用手工黑盒测试，模拟真实师生使用场景，手动操作系统所有功能，逐项记录使用情况、功能问题与系统异常。

## 8. 测试流程
1. 熟悉系统整体功能与业务逻辑
2. 分模块逐项开展单项功能测试
3. 完成整体业务流程联合测试
4. 记录测试问题、BUG与异常情况
5. 提交问题交由开发人员修复
6. 问题修复完成后进行复测验证
7. 汇总整理所有测试资料完成测试

## 9. 测试预期结果
1. 系统所有基础功能运行正常，无卡顿无报错
2. 跑腿全业务流程可顺利走完，订单状态更新准确
3. 错误操作有清晰提示，不会出现系统崩溃
4. 前端操作数据可正常同步存入数据库，数据一致无误
5. 系统操作简单便捷，符合校园跑腿实际使用场景
